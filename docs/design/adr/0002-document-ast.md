# ADR-0002: 中間表現に独自のドキュメント AST を採用する

- 状態: 採用
- 日付: 2026-09-10

## 背景

パーサーとテンプレート エンジンの間に置く中間表現の契約を決める必要があった。候補は 3 つ。

1. パーサーが HTML 断片とメタデータを返す
2. 横断処理に必要な構造だけを粗い IR として抽出し、本文は HTML で持つ
3. 独自のドキュメント AST に正規化する

## 決定

**独自のドキュメント AST** に正規化する。パーサーの責務は AST の構築までとし、HTML の生成は Render 段階に置く。

## 理由

- 目次生成・相互参照解決・見出し収集といった変換を、入力形式ごとに書き直さずに済む。
- HTML を契約にすると、これらの処理が HTML の後処理になり脆くなる。
- 入力形式を追加したときに、変換ロジックを再実装せずに済む。

## 代償

設計と実装のコストが 3 案の中で最も高い。
また、AST が特定パーサーの構造に引きずられる危険があるため、[ADR-0004](0004-asciidoc-parser.md) で
性質の異なる入力形式の実装を早期に投入して抽象を検証する。

## 設計指針

- ノードは「Markdown にある要素」ではなく「文書に必要な要素」で定義する。
- パーサー固有の情報は任意の key/value を持つ `Attributes` に保持し、表現できない構造は `UnknownNode` として原文とともに残す。
- ノードの追加は「2 つ以上の入力形式で必要であること」を要件とする。
